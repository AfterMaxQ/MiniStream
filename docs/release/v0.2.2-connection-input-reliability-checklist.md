# MiniStream v0.2.2 connection and input reliability checklist

Complete the applicable automated, package, and real-device gates before
publishing or updating a v0.2.2 release. A mock or loopback pass does not replace
native Windows/macOS input and hardware evidence.

## Automated fault simulation

- [ ] Drop the first Accept after Hello; the host unlocks after the handshake
      lease and a second client can connect.
- [ ] Leave a host on the pairing screen without confirming; the pairing lease
      expires and discovery becomes available again.
- [ ] Drop either peer's final positive pairing confirmation; both peers
      converge to Streaming during the confirmation grace window.
- [ ] Silence either authenticated peer without sending Disconnect; both sides
      leave Streaming after the liveness deadline.
- [ ] Drop and reorder reliable key and mouse-button edges; applied sequence
      order is preserved and duplicates are not injected twice.
- [ ] Hold keyboard and mouse buttons, then send ReleaseAll, disconnect, expire
      liveness, switch roles, and stop the runtime; every held input is released.
- [ ] Stall the remote tick for at least 40 ms; audio performs bounded clock
      catch-up without an unbounded PLC burst.
- [ ] While a host is handshaking, pairing, or streaming, a second remote does
      not receive an available discovery advertisement.

## Cross-platform input contract

Run every row in both Windows to macOS and macOS to Windows directions:

- [ ] W, A, S, D, Space, Escape, Enter, Tab, Backspace and arrow keys.
- [ ] Left/right Shift, Control, Alt/Option and Meta/Command.
- [ ] Digits, F1-F12, minus, equals, brackets, backslash, semicolon, quote,
      comma, period and slash.
- [ ] Left, right and middle mouse buttons, wheel and ordinary desktop motion.
- [ ] Press a key or mouse button and interrupt Wi-Fi before release; the host
      releases it after liveness expiry.
- [ ] The reserved local shortcut exits remote-input mode and application focus
      loss returns input locally.

## Real connection and recovery matrix

Run Windows to Windows, Windows to macOS, macOS to Windows and macOS to macOS
where hardware is available:

- [ ] 20 consecutive Find devices runs find only an idle broadcasting host.
- [ ] 20 Connect, Pair, Stream and Disconnect cycles complete without restarting
      either application.
- [ ] Five controller force-quit runs return the host to Broadcasting within the
      liveness deadline.
- [ ] Five controlled-host force-quit runs return the remote to browsing within
      the liveness deadline.
- [ ] Five Wi-Fi or cable interruptions recover both applications to usable role
      pages without leaving held input.
- [ ] A 30-minute session has stable video, audio and input without sustained
      queue growth, drift or reconnect failure.

## Windows package and hardware

- [ ] Release build compiles with NVIDIA Video Codec SDK headers and initializes
      H.264 on the same D3D11 device used by desktop capture.
- [ ] HEVC is advertised only when active-device initialization succeeds.
- [ ] With Windows HDR enabled, Controlled mode explains that SDR capture is
      required and does not advertise an unusable session.
- [ ] With Windows HDR disabled, one captured BGRA frame is encoded and produces
      parameter sets and a non-empty IDR bitstream.
- [ ] `MiniStream-Setup.exe` installs the application and Qt/QML runtime, adds
      only the Private-profile application firewall rule, and launches.
- [ ] ViGEmBus remains optional; keyboard and mouse work without it.
- [ ] Uninstall removes the application shortcut and MiniStream firewall rule.

## macOS package and permissions

- [ ] A clean v0.2.2 checkout builds and all available tests pass on the target
      Mac; a v0.1.x application is not used for acceptance.
- [ ] The app bundle contains Local Network and Screen Recording usage strings
      and resolves bundled runtime libraries.
- [ ] Local Network, Screen Recording and Accessibility allow, deny and re-enable
      paths show understandable state.
- [ ] The signed/notarized build is used when credentials are available; otherwise
      the unsigned status is stated with the uploaded DMG.
- [ ] The DMG installs a launchable application and is attached to the matching
      v0.2.2 release.
