# MiniStream v0.1 alpha release checklist

Complete this checklist on clean target builds before tagging a release.

## Build and package

- [ ] Windows Release build completes with the Qt shell enabled.
- [ ] Windows NSIS installer contains the host executable, Qt runtime, MSVC runtime, libsodium, and the bundled ViGEmBus setup.
- [ ] Windows installer detects an existing `ViGEmBus` service and offers the bundled driver install when it is absent.
- [ ] Windows installer starts the normal UAC flow for the driver installer.
- [ ] macOS Release build completes on the target Mac.
- [ ] macOS DMG opens and `MiniStream.app` can be dragged to `Applications`.
- [ ] Installed applications start without Qt, CMake, SDK, or compiler files installed separately.

## Host and client

- [ ] Windows Host reports Video, Audio, Controller, and Network capability states.
- [ ] macOS Client discovers a Windows Host on the same LAN.
- [ ] Both peers display the same six-digit pairing code.
- [ ] Pairing becomes active only after both peers confirm the code.
- [ ] A rejected or cancelled pairing returns both peers to the idle screen.
- [ ] F11 enters and leaves fullscreen; Esc exits fullscreen.
- [ ] Client can enter remote input mode and return keyboard, mouse, and controller routing to the local Mac with the button, Esc, or `Ctrl+Shift+F12`.

## Stream acceptance

- [ ] 1080p60 H.264 hardware encode/decode path is verified.
- [ ] 1440p60 and 4K60 HEVC profiles negotiate the expected limits.
- [ ] 4K60 HEVC Main10 HDR10 path is verified on the target display.
- [ ] Stereo audio remains stable for the acceptance session.
- [ ] One controller reaches the Windows game and rumble returns to the client.
- [ ] FEC restores configured loss and unrecoverable frames trigger bounded IDR recovery.
- [ ] Adaptive bitrate reacts to queue/loss overload without unbounded queue growth.
- [ ] A dropped session can reconnect without restarting either application.
- [ ] Authenticated INPUT and CONTROL packets reject tampering and replay.
- [ ] A 60-minute real-game session has no crash, deadlock, or sustained memory/latency growth.

## Verification commands

```text
cmake --build <build-dir> --config Release
ctest --test-dir <build-dir> -C Release --output-on-failure
python tools/check_ui_copy.py ui
cpack --config <build-dir>/CPackConfig.cmake -C Release
```

Keep generated installers, SDKs, driver binaries, captures, and benchmark dumps out of the Git repository. The package contents are checked from the generated installer or DMG, not from a development checkout.
